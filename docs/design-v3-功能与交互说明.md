# design-v3 功能与交互说明

> **分支**：`design-v3`（远程：`cms2/design-v3` → https://github.com/Goodpipi/CMS2.0demov1）  
> **文档目的**：说明本分支的产品功能、交互逻辑；**明确区分「真实可用能力」与「为演示而 Mock 的数据/启发式逻辑」**。  
> **重要原则**：凡标注为 Mock / 演示的内容，**不得视为已实现的真实产品能力**；它们只是为了演示交互形态而存在。

---

## 0. 阅读约定：三类实现

| 类型 | 含义 | 文档中的写法 |
|------|------|----------------|
| **真实功能** | 有完整交互闭环；状态可持久化或会真正改动产出物 DOM/会话数据 | 「真实」 |
| **真实 UI + 后端可能降级** | 前端走正式 API；服务端无 Key / 失败时可能返回带 `mockUsed` 的结果 | 「真实（API，可能降级）」 |
| **演示 Mock** | 用户曾明确要求 mock，或本地关键词/规则硬编码生成的演示数据与假计划 | 「**演示 Mock（非真实能力）**」 |

## 1. 分支定位与相对关系

### 1.1 分支关系（概念）

| 分支 | 定位 |
|------|------|
| `main` | 较早一版工作台与审阅协作 |
| `design-v2` | 任务优先首页等第二套设计 |
| `design-v3` | 在 design-v2 能力上继续迭代：元素点选修改、Plan 模式、Task Queue、批注标签策略等（**当前工作区可能还有未推送的本地改动**） |

### 1.2 本分支相对「首页+工作台」的产品主线

1. **首页改为任务优先**（不再以大文本框为主入口）
2. **工作台三栏**：引用素材 | 内容预览 | 人机对话
3. **右侧对话区增强**：Agent / Plan、Task Queue、选中元素后用底部输入框修改
4. **PPT 预览可点选元素**；手动调整页不再提供「AI 精准修改」面板
5. **审阅批注**：创作者在有 PPT 审阅任务时可切换「对话 / 批注」

## 2. 角色与全局壳层

### 2.1 角色切换（真实）

- 入口：顶栏 `RoleSwitcher`
- 角色：内容运营（ops）/ 医学（medical）/ 市场（marketing）等
- 影响：
  - **运营**：看到任务优先首页 + 完整工作台创作
  - **审阅者**：首页变为审阅任务列表，进入任务后为审阅专注布局

### 2.2 品牌下拉（真实 UI，无业务效果）

- 顶栏「当前品牌」下拉为界面展示，**不驱动真实品牌数据隔离**。

### 2.3 合规状态条（真实 UI，装饰性）

- 工作台右侧标题旁「合规智能体正在运行中」为状态展示，**不是独立可配置的合规引擎产品功能**。

## 3. 首页（任务优先）— 真实功能

### 3.1 布局与信息架构

- 主标题 / 副文案传达「今天你有什么灵感」类创作引导
- **主 CTA：新建任务**（不再依赖首页大文本框 +「开始创作」作为唯一路径）
- 下方为 **历史任务卡片区** + **分页**

### 3.2 新建任务（真实）

1. 点击「新建任务」
2. 创建新会话并进入工作台
3. 会话写入本地会话存储（`localStorage` 体系）

### 3.3 历史任务（真实 + 空库种子）

| 交互 | 说明 | 类型 |
|------|------|------|
| 搜索 | 按标题/摘要过滤 | 真实 |
| 点击卡片 | 打开对应会话进工作台 | 真实 |
| 删除 | 确认后删除会话 | 真实 |
| 分页 | 默认每页约 6 条 | 真实 |
| 空态 | 引导去新建任务 | 真实 |
| 首次空库 | 可能注入演示会话 | **演示 Mock（种子数据，非线上用户真实历史）** |

### 3.4 知识库 / 素材库入口（真实导航）

- 可进入知识库、素材库相关页面
- 列表中可能含内置示例素材条目 → **演示种子素材，不等于真实 CMS 同步**

### 3.5 审阅者首页（真实列表 + 可能有种子任务）

- 医学/市场角色看到分配给自己的审阅任务
- 打开任务进入审阅专注模式
- 若本地无任务，可能存在种子审阅任务 → **演示 Mock**

## 4. 工作台总览（真实布局）

### 4.1 三栏结构

| 栏 | 名称 | 职责 |
|----|------|------|
| 左 | 引用素材 | 管理本任务引用的知识/素材 |
| 中 | 内容预览 | 展示洞察/文案/图文/图片/PPT/视频等产出 |
| 右 | 人机对话 | 对话、计划模式、队列、批注 |

- 左侧可折叠；折叠后保留窄条展开入口（真实 UI）

### 4.2 任务标题（真实）

- 可点击编辑任务标题并保存到会话

### 4.3 中间空预览入口（真实入口 + 部分 Mock 结果）

当尚无生成内容时，中间区提供：

- **打开本地文件**
- **打开 CMS 文件**

| 路径 | 实际行为 | 类型 |
|------|----------|------|
| 打开本地文件 | 交互入口真实；当前实现会落到演示 PPT 结果，**不解析真实文件内容做版式还原** | **入口真实；结果为演示 Mock** |
| 打开 CMS 文件 | 打开素材选择（CMS Tab）；选中后可进预览 | **选择器真实 UI；CMS 内容多为本地/演示素材，非真实 CMS API** |

## 5. 左侧「引用素材」（真实）

### 5.1 用户可做

- 展开 / 折叠侧栏
- 按分类查看素材
- 上传本地 / 搜索 CMS（选择器）
- 预览素材详情
- 将素材标记为任务引用

### 5.2 说明

- 引用关系进入后续生成请求的素材过滤逻辑（真实前端链路）
- CMS 搜索与默认库内容在演示环境中多为本地构造 → **勿当作已对接生产 CMS**

## 6. 中间「内容预览」（真实容器 + 多种产出）

### 6.1 Tab 体系（真实）

根据生成结果动态出现 Tab，例如：

- 话题洞察 / 话题推荐
- 文案生成
- 图文
- 图片生成
- PPT 大纲 / PPT 生成
- 视频相关
- 团队修改 / Veeva 提交等

切换 Tab 只切换预览态（真实）。

### 6.2 历史版本条（演示向）

- 「查看历史版本」可切换 V1/V2/当前等
- 版本时间与条目多为前端写死的演示列表 → **演示 Mock（非真实版本控制系统）**

### 6.3 PPT 设计预览（真实交互骨架）

当存在 PPT 结果时：

1. 左侧缩略图切换页码（真实）
2. 可显示该页批注数量角标（真实，基于审阅数据）
3. 主舞台展示当前页 SVG/预览（真实渲染）
4. **点击页面元素可选中**（真实 DOM 选中）
5. 工具栏保留 **画笔 / 清除**（真实：在预览上叠加笔迹；**不是服务端持久化的正式批注系统**）
6. **手动调整**：打开 VisualEditor（真实 SVG 编辑）

#### 6.3.1 选中元素 → 右侧改写（关键）

| 步骤 | 行为 | 类型 |
|------|------|------|
| 1 | 在 PPT 舞台点击非背景元素 | 真实选中 |
| 2 | 再次点击同一元素取消选中 | 真实 |
| 3 | 右侧出现「已选中 · 第 x 页 · 元素名」提示 | 真实状态展示 |
| 4 | 在底部输入框输入自然语言并发送 | 真实触发 |
| 5 | 短延迟后按规则改 fill/字号/文案等并写回 slide.svg | **演示 Mock：本地关键词启发式（`elementAiEdit.ts`），不是大模型精准改版** |

> 用户明确要求「直接帮我 mock」的能力之一。**界面像 AI 改元素，实现是本地规则引擎。**

### 6.4 图片预览 / 审阅采纳（真实 UI + API）

- 多图勾选、打开编辑、团队审阅前后采纳/恢复等
- 生成与海报编辑走 API → **真实（API，可能降级）**

### 6.5 其它产出预览

- 文案编辑、大纲编辑器、图文富文本、视频卡片等：编辑器与预览多为真实前端组件
- 部分「一键生成图文」等聊天捷径会直接灌入 `workspaceMocks` → **演示 Mock**

## 7. 手动调整（VisualEditor）— 真实编辑

### 7.1 PPT 页进入手动调整（`allowBrush = false`）

用户可：

- 点选 / 拖拽元素
- 左侧改属性（文本、颜色、字号、描边、透明度、图层等）
- 插入形状、复制删除、撤销重做
- **保存精调并返回** / **返回**

**已移除（本分支当前行为）：**

- 右侧「AI 精准修改」文本框与「AI 修改选中元素」按钮  
  → PPT 手动调整页 **不再提供** 页内 AI prompt 改元素（改元素改走工作台预览点选 + 底部输入框的演示链路）

### 7.2 图片进入编辑（通常 `allowBrush = true`）

- 可用画笔圈选 + 「AI 局部修改」生成新版本
- 生成调用 `generatePosterEdit` → **真实（API，可能降级）**
- 也可切到设计编辑做手动属性调整（真实）

## 8. 右侧「人机对话」

### 8.1 标签策略（真实）

| 条件 | 顶部标签 |
|------|----------|
| 当前会话 **没有** PPT 审阅任务且没有批注 | **不显示**「对话」单标签，直接进入对话区 |
| 有 PPT 审阅任务 / 已有批注 / 已完成审阅 | 显示 **对话 \| 批注** |

批注能力本身未删除：可查看按页批注线程、回复批注（真实，落本地审阅存储）。

### 8.2 对话消息流（真实 UI + 混合后端）

- 用户消息 / AI 消息气泡、快捷 chips、图片消息上的「图片修改」等
- 发送后路由到意图识别、向导、API 或本地 mock 命令

### 8.3 Composer：Agent / Plan（交互真实，Plan 内容为 Mock）

#### Agent 模式（默认）

- 底部输入框发送 → 走正常创作意图链路  
- **真实产品主路径**（下游 API 可能降级）

#### Plan 模式（Codex 风格切换）

| 交互 | 说明 | 类型 |
|------|------|------|
| Agent / Plan 分段切换 | 底部工具栏 | 真实 UI 状态 |
| Shift+Tab | 切换模式 | 真实快捷键 |
| Plan 下占位与按钮文案 | 「生成计划」等 | 真实 UI |
| 发送后的 Proposed Plan | 固定结构 HTML 计划步骤 | **演示 Mock（非模型规划）** |
| chips：按此计划执行 / 继续完善 / 切换到 Agent | 切回 Agent 或填输入框 | 真实状态切换；**不自动执行真实多步工程计划** |

> Plan 模式用于演示「先计划再执行」的交互壳，**不是 Cursor/Codex 同级的真实只读规划智能体。**

### 8.4 Task Queue（演示 Mock UI）

位置：对话输入区上方，可折叠面板。

**已 Mock 的初始队列（`src/lib/taskQueue.ts`）** — **演示数据，不是真实后台任务系统：**

- 1 条 Running（例如改第 2 页标题）
- 若干 Queued（图文安全性、封面副标题、主视觉等）

**面板内真实可用的「本地交互」：**

- 展开 / 折叠
- Queued 项上移 / 下移
- 「立即执行」仅改变本地队列状态（Running/Queued 标记）
- 移除队列项

**明确不是真实能力：**

- 队列 **不会**自动串行调用生成 API
- 「立即执行」**不会**真正跑完改 PPT/图文的生产流水线
- 队列数据重启后回到 Mock 种子（除非另做持久化；当前为内存初始 Mock）

**已去掉的相关入口（当前分支行为）：**

- 「加入队列」按钮
- 「Alt+Enter 加入队列」提示与快捷键
- 智能引导 chips（快捷前缀引导条）

### 8.5 底部输入与附件（真实 UI）

- ＋ 打开素材选择（聊天附件）
- 模型下拉目前仅 GPT-5.5 → **展示用**
- 发送 / Enter 发送
- 选中元素时 placeholder 变为元素修改引导文案（真实状态）

### 8.6 已移除的右侧能力（相对中间迭代）

- **「全部任务」标签及筛选/详情/取消/重跑** 已去掉，由 Task Queue 演示面板替代  
- 勿再把「全部任务列表」当作本分支功能

## 9. 审阅与批注（真实协作闭环，本地存储）

### 9.1 创作者发起团队审阅（真实）

1. 在预览对 PPT / 图片 / 文案等点「提交团队审阅」
2. 选择审阅角色、截止时间等
3. 写入审阅任务（localStorage）
4. 满足条件后右侧出现「对话 / 批注」

### 9.2 审阅者（真实）

1. 审阅者首页打开任务
2. 进入审阅专注布局（预览 + 批注侧栏）
3. PPT：翻页预览（一般为图片预览，**不是**创作者那套可选中 SVG）
4. 对当前页添加批注
5. 完成审阅 → 回首页；创作者侧可看到批注与完成状态

### 9.3 创作者查看批注（真实）

1. 切到「批注」
2. 按当前预览页过滤显示
3. 可回复；回复带角色颜色区分
4. 中间 PPT 缩略图可显示批注数量

### 9.4 种子审阅数据（演示 Mock）

- 空环境可能 `seedReviewTasksIfEmpty` 注入演示审阅任务  
- **这是演示数据，不是真实组织里的审批流 / OA**

### 10.2 Demo Scenario 脚本

仓库内有学术/患者/HCP 等脚本化演示流，但 `isDemoMode()` 当前恒为关闭时，**默认不会作为正式路径启用**。

## 11. 「明确要求 Mock」的清单（务必单独看待）

以下是对话中明确要求「直接 mock」或为演示交互而加入的部分，**文档与评审时不得写成已上线 AI/任务中台能力**：

| 项目 | 位置 | 演示内容 | 真实能力边界 |
|------|------|----------|----------------|

## 12. 关键交互流程图（逻辑）

### 12.1 创作者改 PPT 某一元素（演示 AI）

```
预览点选元素
  → 右侧显示已选中 chip
  → 底部输入 prompt 并发送（Agent）
  → 本地启发式改 SVG
  → 写回 pptResult / 当前版本 slides
  → 对话区出现结果说明
```

### 12.2 审阅批注

```
创作者提交团队审阅
  → 审阅者打开任务并按页批注
  → 完成审阅
  → 创作者右侧出现「批注」
  → 按页查看并回复
```

### 12.3 Plan 模式（演示）

```
切到 Plan
  → 输入目标并「生成计划」
  → 展示固定结构 Proposed Plan
  → 「按此计划执行」仅切回 Agent 并给后续 chips
  → 不会自动逐步改仓库/产出物
```

## 14. 给评审 / 产品的一句话结论

**design-v3 的价值在于交互形态**：任务优先首页、三栏工作台、PPT 点选、底部改元素、Plan 切换、Task Queue 面板、批注标签策略。  

其中 **Task Queue 展示数据、Plan 计划正文、元素「AI」改写结果、本地打开文件得到的 PPT、空库种子会话/审阅**，都是 **按需求 Mock 的演示层**；**不要把它们表述为已经接好的真实任务调度、真实规划模型或真实文件解析能力。**
